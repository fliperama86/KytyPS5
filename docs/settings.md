# Settings

Every runtime gate this fork adds or relies on. Game-specific and investigation-only
behaviour is off unless something on this page turns it on, so `main` stays safe for
other titles. `kyty_emulator.exe --help` prints the full option list, including the
window, user, and path options omitted here.

> **This line (`des-on-599`, built on upstream PR 599, 2026-09-13):** the flags of the fork's
> sync-point, GPU-descriptor-fetch and frame-replay experiments do not exist here:
> `--bda-async-protect*`, `--frame-capture*`, `--gpu-descriptors`, `--gpu-fetch-side-effects`,
> `--gpu-indirect`, `--gpu-indirect-draws`, `--gpu-prologue-table`, `--gpu-readback-*`,
> `--gpu-srt-reads`, `--gpu-submit-*`, `--replay*`, and `KYTY_DEBUG_SRT_STATS`, `KYTY_GPU_FETCH_*`,
> `KYTY_SRT_PACKED`, `KYTY_WATCH_ADDR`, `KYTY_GUARD_SELECT`, `KYTY_PROLOGUE_IMPORT_FIRST`. The PR's
> own additions: `KYTY_DES_PROFILE=0` switches its Demon's Souls profile off at launch.


## Command-line flags

| Flag | Default | What it does | Exists for |
| --- | --- | --- | --- |
| `--shader-lds-waitcnt-barrier <true\|false>` | `false` | Emits a subgroup-scope `OpControlBarrier` for every `S_WAITCNT` in a compute shader that uses LDS. | Demon's Souls, whose waves exchange LDS data after `S_WAITCNT` without an `S_BARRIER`. It costs frame rate and is not needed by other titles. |
| `--shader-storage-bounds-check <true\|false>` | `true` | Wraps each storage-image write in an `OpImageQuerySize` compare and branch; `false` emits the plain `OpImageWrite`. | The Demon's Souls GPU-crash investigation (out-of-bounds `IMAGE_STORE` losing the device). On by default because an unbounded write can take the device down on any game. |
| `--graphics-debug-dump <true\|false>` | `false` | Names Vulkan objects, dumps pipelines and shaders, and enables `VK_EXT_device_fault` plus NV diagnostic checkpoints. | Device-loss and GPU-fault investigations. |
| `--thread-affinity <auto\|none>` | `auto` | `auto` enumerates the host L3 caches at startup and, when there are at least two of unequal size in one processor group, pins the render and presentation threads to the largest cache's logical processors and every guest thread to the rest, logging one line with the sizes and the derived masks. A uniform host, a single L3 cache, more than one processor group and every non-Windows platform derive nothing. `none` derives nothing anywhere. | Multi-CCD hosts with asymmetric L3, such as the Ryzen 9 9950X3D; see the CCD affinity section in [demons-souls-performance.md](demons-souls-performance.md). |
| `--gpu-descriptors <true\|false>` | `false` | Shaders evaluate eligible buffer descriptors in-shader through the BDA page table instead of the render thread materializing them; see [gpu-descriptor-fetch.md](gpu-descriptor-fetch.md), stage 1. Experimental. | Demon's Souls per-draw cost; measure with the parked Nexus protocol. |
| `--gpu-srt-reads <true\|false>` | `false` | The other half of the same design, stage 1b: the shader also evaluates the flattened SRT scalar reads (`srt_reads`) in its prologue instead of loading them from the `FlattenedSrt` binding, which the binding layout drops once every slot of a program is lowered. **Only has an effect with `--gpu-descriptors true`.** A slot flagged clean, a program with side effects, and the indirect-image search table stay on the host. Measured on nexus-6: 128 programs and 6,926 of 7,017 slots lowered, no feedback mismatch, the image unchanged, and `EvaluateRuntimeSourcesImpl` down 0.8% -- the zone is fixed per-call cost, not the SRT reads. Worth 0.5 ms a loop of `RebindBuffers` and `FindBuffers`, which is the whole effect. | Roadmap item 2, the descriptor half; kept because it is correct and free while off, and because it is the measurement that says where the remaining 26% actually is. |
| `--gpu-prologue-table <true\|false>` | `false` | A second BDA page table, read only by the shader prologue -- the descriptor roots and flattened SRT reads `--gpu-descriptors` and `--gpu-srt-reads` lower. A page a registered buffer covers holds that buffer's mirror, as the data table does; every other mapped page holds the page itself inside guest memory imported with `VK_EXT_external_memory_host`, so a prologue read can never miss. It lives in the upper half of the `BdaPagetable` buffer and counts its misses in a dword past the `FaultBuffer` bitmap, so no stage writes a descriptor it did not write before. On nexus-6 both page tables miss **0 a loop and 0 in loop 1** with the image unchanged and the host side free -- and it costs **2.4 ms a loop** on `--gpu-descriptors true`, all of it in the prologue's page-table lookup itself, so it stays off; see [sync-points-design.md](sync-points-design.md), "Step 1". Needs the extension; without it nothing is imported and behaviour is unchanged. | Step 1 of the artifact-free path: the precondition for removing the render thread's sync points, and the measurement that prices the second lookup and the import for real. |
| `--gpu-fetch-side-effects <true\|false>` | `false` | Lifts stage 1's side-effect rule for **compute** programs: a program that writes or atomically updates a buffer or an image, or uses DMA, evaluates its read-only buffer descriptor roots and its flattened SRT reads in the shader prologue like any other program, instead of staying on the render thread as a whole. The written and atomic resources themselves keep their host binding. The prologue carries a safety net: if any root it evaluates is invalid (a page the import refused, or nothing mapped), the entry point returns before the program's first side effect, sets the program's `DescriptorFeedback` bit -- which routes the next dispatch to the CPU path -- and counts itself in the dword behind the prologue table's miss counter. **Only has an effect with `--gpu-descriptors true` and `--gpu-prologue-table true`**, because without the prologue table a root read can miss and a producer would store the zero it read (docs/investigations/gpu-descriptors-stage1-crash-2026-09-11.md). Measured on nexus-6: read faults 89 a loop to **22** with the flat-read faults gone entirely, and **the hard stop fired** -- the loop is 19 ms slower (78.3 to 97.3 median), the safety net fires 160 to 2,090 times a loop instead of never, and one 40-loop run in two died on a texture descriptor a producer left behind. Neutral on title-2. It stays off; see [sync-points-design.md](sync-points-design.md), "Step 2", for what has to change first. | Step 2 of the artifact-free path: the 60 read faults a loop item 1b attributes to compute programs with side effects, and the measurement that says per-wave prologue evaluation is the wrong shape for them. |
| `--gpu-indirect <true\|false>` | `false` | Vulkan consumes indirect **dispatch** arguments in place (`vkCmdDispatchIndirect` against the guest argument buffer) instead of the render thread draining the device to read them back; see [performance-roadmap.md](performance-roadmap.md), item 1. The `DISPATCH_INITIATOR` thread-dimensions form keeps the readback, because the host has to divide those counts by the shader's group size. Worth 3.2 ms a loop of the parked Nexus's 71.8. | Demon's Souls, whose compute shaders write their own dispatch arguments; measure with the frame-replay bench. |
| `--gpu-indirect-draws <true\|false>` | `false` | The same for indirect **draws** (`vkCmdDrawIndexedIndirect` / `vkCmdDrawIndirect`, one command each). Independent of `--gpu-indirect`; separate because it measures **neutral** in replay — it removes the remaining 9,262 argument syncs a loop but pays a buffer-cache lookup of the argument block per draw and binds the whole `INDEX_BUFFER_SIZE` range instead of the draw's slice, which costs the same 3.2 ms back. `DRAW_INDIRECT_MULTI`, legacy quad and rect lists, 8-bit indices, NGG/mesh assembly and a custom primitive-reset index stay on the readback path. | Keeping the dispatch win once the draws are the only readback left, which only an end-to-end run can show. |
| `--gpu-readback-producer-wait <true\|false>` | `false` | A readback the render thread takes on a GPU-dirty page records its copy on a separate command buffer, submitted on the graphics queue behind the producing submission's tick alone and signalling its own timeline, instead of `Finish()`-ing the open command buffer and waiting for the whole queue; see [performance-roadmap.md](performance-roadmap.md), item 1b. It applies only when the buffer cache can name the newest submission that wrote every byte being copied (a direct-mapped 64 KiB block table) and that submission has already retired: 29 of the 97 read faults a loop of the parked Nexus. Those 29 go from 11.6 to 3.3 ms a loop, and the loop does not move, because the work the fast path leaves unsubmitted is drained by the next fault whose producer is still in the open command buffer. **Measured neutral to 0.3 ms worse; kept off, and kept because it is the measurement that closes item 1b.** | Item 1b; the other 68 read faults a loop are the thing that would have to change first. |
| `--gpu-readback-diagnostics <true\|false>` | `false` | Counts and times every read fault the render thread takes on a GPU-dirty page, with the shader hash, stage and root kind the SRT evaluator was on, the faulting address, the bytes the 512 KiB download window covers, the submission and the draw-and-dispatch clock that produced the page, whether that submission had retired, and the wait. Prints one summary line and writes `readback-faults.json` beside `replay-report.json`. Costs render-thread time -- a mutex and two `steady_clock` reads a fault, a block-table write per GPU-claimed range, one store per packed-program instruction -- so never leave it on in a measured run. | The characterisation behind item 1b. |
| `--gpu-submit-interval <num>` | `0` | "Periodic submits" of [performance-roadmap.md](performance-roadmap.md), item 1b. After every N draws and dispatches the render thread records, the open command buffer is ended and submitted **without a wait**, at the first boundary that is outside a dynamic-rendering pass, so the device executes it while the CPU keeps recording; `0` keeps the old behaviour, one submission per guest submission or drain. The pass-boundary condition is what makes it pay: splitting an open pass stores and reloads every attachment and can repeat a clear, and measured 7 ms a loop *worse*. Worth about **3.2 ms a loop** of the parked Nexus's 73.7 at N=16 (the device wait inside the read faults falls from 38 to 32 ms a loop for 120 more submissions), the same on `--gpu-descriptors true`, neutral on title-2, image unchanged. Below the 5 ms the experiment was run for, so it stays off. | Item 1b's third lever, the only one that touches the 70% of read faults whose producer is still in the open command buffer. |
| `--gpu-submit-after-writes <true\|false>` | `false` | The same, additionally right after any draw or dispatch that claimed a range for the GPU (`ObtainBuffer` with `is_written`) -- the producer a readback is about to ask for. It cuts the wait hardest of any configuration (23 ms a loop against 38) but takes 1,738 submissions a loop instead of 197, and at roughly 20 us each that costs more than it saves: **95.7 ms/loop gpu against 73.7.** Kept only because it is the measurement that prices a submission. | Nothing; it is the negative half of the same experiment. |
| `--bda-async-protect <true\|false>` | `false` | Design P of [bda-sync-design.md](bda-sync-design.md). A BDA scan that uploads a CPU-dirty page no longer re-protects it on the render thread: it clears the dirty bit, leaves the page writable (state U) and queues the region for a helper thread, which protects the whole batch in one call per contiguous run, and marks the pages landed. The next scan or bind that covers a landed page uploads it a second time -- it may have been written between the upload and the protection taking effect -- and the page becomes protected and clean. A landing moves no generation of its own; instead every submission, before its first draw, waits for the helper to drain and then forces one scan, which is the only place a stale mirror could otherwise be read. A written upload is not deferred: the GPU claims the range in the same call and protects it at no-access anyway. On the replay bench the render thread's upload path makes **0** protect calls against 926 a loop off (`--gpu-descriptors true`), and the image is unchanged. Costs milliseconds in replay, where a protect call is nearly free; the win is in the game, where one costs 5.4 us. | Roadmap item 2, the sync half: 1,342 render-thread `NtProtectVirtualMemory` calls a frame inside BDA scans, 7.3 ms of a 103 ms frame. |
| `--bda-async-protect-affinity <guest\|render>` | `guest` | Which CPU group the helper thread above runs on. Measured both ways on nexus-6, 40 loops, two repeats: guest **83.25** ms/loop gpu, render **85.42** -- the same reason the replay writer is slower on `render`, that group holds the render and presentation threads. | Choosing the helper's CPU group by measurement rather than by guess. |
| `--profiler-direction <None\|Network>` | `None` | Starts the Tracy profiler server. `Play Demon's Souls.cmd profile` passes it. | Frame-rate and render-thread zone work. |
| `--vblank-frequency <num>` | `60` | Virtual vblank rate in hertz, clamped to 30..360. Presentation is paced by it, so it is the quantum of the replay harness's `ms/loop`; raise it to 360 when a replayed loop is faster than 16.7 ms, or steer by `ms/loop gpu`, which is not paced. | Frame-replay benches; present-pacing experiments. |
| `--vulkan-validation <true\|false>` | `false` | Vulkan validation layers. | General debugging. |
| `--gpu-assisted-validation <true\|false>` | `false` | GPU-assisted validation; implies `--vulkan-validation`. Very slow. | Finding out-of-bounds shader accesses. |
| `--spirv-debug-printf <true\|false>` | `false` | Routes `debugPrintfEXT` from generated SPIR-V to the console. | Shader recompiler debugging. |
| `--shader-validation <true\|false>` | `false` | Runs the SPIR-V validator on every generated module. | Shader recompiler debugging. |
| `--shader-optimization-type <None\|Size\|Performance>` | `None` | SPIR-V optimizer pass level. | Shader experiments. |
| `--shader-log-direction <Silent\|Console\|File>` | `Silent` | Dumps decoded RDNA2, IR, and SPIR-V (folder from `--shader-log-folder`). | Shader recompiler debugging. |
| `--command-buffer-dump <true\|false>` | `false` | Writes guest command buffers (folder from `--command-buffer-dump-folder`). | GPU command-stream investigations. |
| `--frame-capture <dir>` | off | Arms the frame capture of the replay harness and writes it into `<dir>`, created if missing: `manifest.json`, `ranges.bin`, `memory.bin`, `dirty-pages.bin`, `dirty-events.bin`, `churn-events.bin`, `prepare-events.bin`, `submissions.bin`, `registers.bin`, `videoout.bin`, `prt.bin` (the partially-resident-texture apertures) and `shaders.bin` (the AGC shader map). The capture quiesces the GPU thread, flushes GPU-owned buffers and images back into guest memory, and records the frame's submissions in the order the GPU thread started processing them. Ranges it cannot read back are listed under `gaps` in the manifest. Off, the recorder does nothing at all. See [frame-replay.md](frame-replay.md). | Building the replay bench that measures render-thread work without the game. |
| `--frame-capture-at <num>` | trigger file | Captures the GPU frame with that `GuestGpu` frame number. Without it the capture waits until a file named `trigger` appears inside the capture directory, tested once per `Done()`, and takes the frame that ends next. | Capturing a fixed frame from a script, or a scene a navigation script parks on. |
| `--frame-capture-frames <num>` | `1` | Records that many consecutive frames from the trigger frame on; the memory, register, video-out, aperture and shader snapshot is taken at the end of the last of them. Useful for measuring what changes between frames (it is what showed the parked Nexus has no buffer churn); only the last frame of a capture replays on a title whose guest advances a label per frame, see [frame-replay.md](frame-replay.md), phase E. | Measuring frame-to-frame churn; capturing a sequence. |
| `--frame-capture-exit <true\|false>` | `true` | Ends the process once the capture is written and flushed. `false` leaves the game running. | Scripting one capture per launch. |
| `--readback-linear-images <true\|false>` | `false` | Reads writable linear images back to guest memory on submit. | Titles that read GPU-written linear images on the CPU. |
| `--playgo-hack` | off | Uses the bundled PlayGo stub fallback when the title's chunks do not load. | Games that stall in PlayGo. |
| `--redzone` (Windows) | off | Protects the guest SysV red zone across host callbacks. | Guest-fault investigations. |
| `--rd` | off | Loads the RenderDoc capture layer. | Frame captures. |
| `--replay <dir>` | off | Starts the emulator without a game, restores the frame capture in `<dir>` (guest memory, video-out registration, command-processor registers) and feeds its submissions through the real `GuestGpu` queue in a loop, then prints milliseconds per loop and writes `replay-report.json` next to the capture. Cannot be combined with `--game`; every other flag, `--gpu-descriptors` and `--present-mode` included, still applies. See [frame-replay.md](frame-replay.md). | Measuring render-path changes in under a minute instead of a 40-minute end-to-end run. |
| `--replay-timeout <ms>` | `600000` warm-up, `2000` measured | How long a replayed loop may take before the replay declares the GPU thread hung and gives up, warm-up and measured loops alike. The warm-up compiles every pipeline the frame touches; with `--gpu-fetch-side-effects true` the compute modules are large and the driver takes about a second over each of 286 of them on a cold cache, and the loop itself is far past the 2 s a measured loop is allowed. | Benching a configuration whose loops are slower than the watchdog. |
| `--replay-loops <num>` | `20` | Loops `--replay` runs. The first loop is a warm-up and is excluded from the statistics. | Trading measurement time against noise. |
| `--replay-frames <num>` | every recorded frame | How many of the capture's frames one loop replays, counted from the **last** one back: the last frame is the one the memory snapshot ends on. `1` on a multi-frame capture replays only that frame. | Replaying the tail of a multi-frame capture. |
| `--replay-dirty-set <once\|loop>` | `once` | Whether the capture's recorded CPU-dirty page set is marked once at restore (`once`) or before every replayed frame (`loop`, the phase B to D behaviour). The set is pages the guest wrote before the frame and the GPU has not consumed; in the game they stay dirty across frames, so re-marking them every frame inflates what each BDA scan walks (17.2 dirty ranges a scan against the game's 4.3). The frame's recorded CPU writes are replayed per frame either way. | Matching what the game's BDA scans actually see. |
| `--replay-spin-threads <num>` | `0` | Spins that many host threads on the guest CPU group for the length of a replay, imitating the game's job-system workers, which busy-wait in guest code. Each is one relaxed atomic load and a `YieldProcessor` per iteration: no syscalls, no writes, no memory traffic. Measured on the parked Nexus it costs the loop half a millisecond and does not reproduce the game's cost per BDA scan, which is what it was built to test ([frame-replay.md](frame-replay.md), phase E). | Testing whether a replay is too fast because the machine around it is idle. |
| `--replay-writer <none\|guest\|render>` | `none` | One host thread on that CPU group rewrites the memory of every dirty mark the replay applies -- one volatile load and a store of the same value per 64-byte line, over the 4 KiB tracker pages the mark dirties, so the bytes do not change and the lines end up dirty in that core's cache. The handoff is synchronous: the thread applying the mark waits for the writer before it goes on, and that wait is timed and reported apart from `ms/loop` (`writer_wait_us`, `writer_bytes`, `writer_skipped_pages` in `replay-report.json`). The rewrite follows the mark rather than preceding it, because before the mark the pages are still GPU-protected and resolving that fault needs the GPU thread, which is the thread waiting. Tests whether a replayed BDA scan is cheap because the lines it copies are cold in DRAM ([frame-replay.md](frame-replay.md), "Writer imitation"). | Reproducing the game's cost per BDA scan in the replay bench; roadmap item 2 ([bda-sync-design.md](bda-sync-design.md), step 0). |
| `--replay-image <path>` | off | After the last loop, writes each replayed frame of it as raw, tightly packed, in the video-out pixel format the guest chose, to `<path>-f1.raw`, `<path>-f2.raw` and so on, plus `<path>` itself for the last frame, each with a `.json` sidecar giving width, height, format, bytes per pixel and stride. Demon's Souls presents `A2B10G10R10_UNORM_PACK32`, not an 8-bit format; `_Build/replay-image-compare.py` decodes every format the presenter can produce. | Diffing a replayed frame against the capture screenshot. |

## Environment variables

All are read once, on the code path named, and all are off when unset except the three affinity
masks, which fall back to whatever `--thread-affinity` derived. The root `Play Demon's Souls.cmd`
sets the `KYTY_DEBUG_DES_TOUCH_*` group.

| Variable | Default | What it does | Exists for |
| --- | --- | --- | --- |
| `KYTY_DEBUG_DES_TOUCH_TRACE` | unset | `1` installs the guest `TouchManager` probes. Requires PPSA01342, `01.005.000`, `eboot.bin`; any other title logs one line and leaves the hooks uninstalled. A probe-byte mismatch on a matching title is still fatal. | The Demon's Souls collision-list race workaround; without it the game does not reach gameplay. |
| `KYTY_DEBUG_DES_TOUCH_SERIALIZE` | unset | `1` serializes `TouchManager` traversal and mutation behind a host recursive mutex. | Same workaround, lighter mode. |
| `KYTY_DEBUG_DES_TOUCH_FULL_CAPTURE` | on unless serializing | `1` records every list mutation. Implied when `KYTY_DEBUG_DES_TOUCH_SERIALIZE` is not set. | Collision-list race report evidence (`tools/analyze_touch_trace.py`). |
| `KYTY_DEBUG_DES_TOUCH_LIST` | unset | `1` dumps a bounded snapshot of the guest collision list on a fault at `eboot.bin+0xd8c1f5`. | The same race investigation. |
| `KYTY_DEBUG_GUEST_FAULT` | unset | `1` prints guest registers and a code window for an unhandled guest exception. | CPU-fault investigation. |
| `KYTY_DEBUG_SRT_STATS` | unset | `1` accumulates the descriptor mix of every (draw, stage) event and writes `_Diagnostics/srt-stats-<yyyymmdd-hhmmss>.json` under the runtime directory at exit and every 600 frames, overwriting the same file. Records descriptor-source counts by kind, buffers-only and DMA draws, push-constant overflow, distinct buffer and vertex layouts per shader, SRT flat-program size and memory reads, and pipelines/shaders per frame. It also turns on the evaluator's own `srt_chase` counters (guest reads, dependent read depth, distinct lines and pages an evaluation touches). Every hook is inert when unset. | Sizing a GPU-side descriptor fetch design. |
| `KYTY_GPU_FETCH_SKIP_DIAG`, `KYTY_GPU_FETCH_DUMP_HASH` (hex), `KYTY_GPU_FETCH_DUMP_TARGET`, `KYTY_GPU_FETCH_PEEK` (hex), `KYTY_WATCH_ADDR` (hex), `KYTY_PROLOGUE_IMPORT_FIRST` | unset | Step 2 fact-check diagnostics (docs/sync-points-design.md): print the programs the safety net sends back and evaluate all their sources; replay one prologue target's root on the CPU with every read logged and its pages' table entries, mirror and import bytes; print every dispatch's first user-data register and CPU evaluation result for one program; for that program, the shader records its first failing read (address, reason, V# dwords) and first user-data value into the prologue counter dwords; print every backing write covering an address; point prologue entries of GPU-clean pages at the import. All inert when unset; console output needs `--printf-direction Console`. | Diagnosing step 2. |
| `KYTY_SRT_PACKED` | set | `0` keeps every resource plan on the compile-time flat program instead of the packed sequential schedule the evaluator normally builds and runs ([gpu-descriptor-fetch.md](gpu-descriptor-fetch.md), "Packed flat program"). Read once, at plan compile time; both forms produce the same values. | A/B of the packed evaluator from one binary, and a switch if it ever misbehaves. |
| `KYTY_DEBUG_NV_FAULT_DETAILS` | unset | `1` adds `VK_NV_device_diagnostics_config`. Only has an effect with `--graphics-debug-dump true`. | NVIDIA fault-detail capture. |
| `KYTY_DEBUG_RESOURCE_TRACE` | unset | Set to a file path: records the last 128 compute dispatches with their bindings and writes them there on device loss. | GPU crash report. |
| `KYTY_DEBUG_GPU_FAULT_FILE` | unset | Set to a file path: saves the vendor fault binary from `VK_EXT_device_fault`. Needs `--graphics-debug-dump true`. | GPU crash report. |
| `KYTY_DEBUG_SERIALIZE_DISPATCH` | unset | Set to anything: flushes and waits after every compute dispatch. Very slow; isolates which dispatch faults. | GPU crash report. |
| `KYTY_GPU_THREAD_AFFINITY` (Windows) | derived | Hexadecimal CPU mask pinned onto the render thread `Thread_Gpu` with `SetThreadAffinityMask`. Logs one line with the thread id and mask. Overrides the mask `--thread-affinity auto` derived for that thread; unset, empty or unparseable keeps the derived mask. | Scheduling experiments on multi-CCD hosts; see the CCD affinity section in [demons-souls-performance.md](demons-souls-performance.md). |
| `KYTY_PRESENT_THREAD_AFFINITY` (Windows) | derived | The same, for the video-out presentation thread. | Same. |
| `KYTY_GUEST_THREAD_AFFINITY` (Windows) | derived | The same, for the guest main thread and every thread the guest creates through `pthread_create`. | Same. |
| `KYTY_BORDERLESS` (macOS) | unset | Set to anything: creates a borderless SDL window, avoiding macOS 26 title-bar exceptions under Rosetta. | Upstream macOS workaround. |
